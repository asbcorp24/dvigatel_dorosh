# Испытание Modbus RTU без пуска двигателя

1. На INNOVERT сохранить существующие параметры, затем настроить `P50.00=1`, `P50.01=13` (клеммный интерфейс 38400), `P50.02=00` (8N1), если это подтверждено заводским руководством и фактическим меню.
2. Подключить RS-485 A/B с правильной полярностью, PE/экран согласно схемам. Не соединять интерфейс с неуказанной землёй без проверки схем и изоляции.
3. В PLC200 определить реальный номер COM-порта через конфигуратор/паспорт, указать его в `RTU_ComPort` программы. Сначала `RTU_WriteEnable=FALSE`, `CommissionEnable=FALSE`.
4. Загрузить в ПЛК проект, запустить программу в безопасном режиме, наблюдать `RTU.PortActive`, `RTU.OkCount`, `RTU.ErrorCount`, `RTU.LastFailedOperation`, `GVL_DriveIO.SpeedRaw/StatusRaw/CurrentRaw/FaultCodeRaw`.
5. Добиться устойчивых ответов FC03; текущая версия выполняет чтение последовательным планировщиком `OCL.MB_SerialRequest`. При ошибках проверить порт, P50, A/B, терминаторы, адрес Modbus и отсутствие второго владельца COM.
6. Проверить, что при отключении RS-485 / питании ПЧ `RTU.Healthy` становится FALSE, а `GVL_PC.Holding[116]` не разрешает движение. Учесть, что физический привод может продолжить вращение — аппаратная безопасность отдельно.
7. На неподвижном валу зарегистрировать `0x8107` и `0x8118`. Для доказательства обратной связи PG проверить показания по процедуре производителя, без неоправданного вращения опасного механизма.
8. До проверки декодера скорости и статуса `PGFeedbackProven = FALSE`, `DriveStatusDecoded = FALSE`, `DriveSpeedScalingProven = FALSE`; записи FC06 остаются закрыты.
9. Только после проверки регистров, защит и независимого аппаратного останова перейти к тестам записи FC06 со специально оформленным разрешением и протоколом пусконаладки.

## Интервалы
- Цикл ST задачи: 20 мс.
- Тайм-аут операции: 300 мс, retries 0 (ошибка диагностируется и следующий цикл пробует новое чтение).
- Признак свежести скорости и статуса: возраст каждого успешного ответа меньше 0,8 с; все показания: до 2 с.
- Порог времени и частоту опроса уточнить по фактическим ответам ПЧ, особенно при помехах / высокой нагрузке.

## Критерии
- Ни одной Modbus FC06 команды при `RTU_WriteEnable=FALSE`.
- Один активный RTU запрос на шине.
- Подтверждённое завершение передачи перед следующим запросом.
- При потере ответа старые значения становятся недостоверными.
- Признак остановки не определяется только заданной частотой; он требует независимой проверенной обратной связи.
