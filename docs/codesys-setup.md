# Сборка CODESYS 3.5 для ОВЕН ПЛК200-04-CS

## Состояние
В репозитории хранятся **исходники ST для отдельных объектов CODESYS**. Это не экспорт устройства *.project/*.projectarchive, не утверждается, что выполнена компиляция на конкретном таргете. ПЛК должен оставаться в STOP, пока не пройдены аппаратные и программные проверки.

## Создайте проект
1. Установите CODESYS V3.5 и **официальный пакет таргета ПЛК200** соответствующей версии/прошивки ОВЕН.
2. Создайте проект ПЛК200-04-CS.
3. Добавьте DUT `E_MotorState`, DUT `ST_MotorCommand` из `codesys/00_DUT_MotorTypes.st` **как два отдельных DUT**.
4. Создайте GVL `GVL_PC`, `GVL_DriveIO` из файлов 01 и 07.
5. Создайте Function Block `FB_Pt100Protection`, `FB_Heartbeat`, `FB_ConfirmedStop`, `FB_MotorMotion`, `FB_DriveCommand`; поместите соответствующий ST в каждый объект.
6. Создайте Program `PRG_MotorMain` из файла 08 и назначьте его на циклическую задачу 20 мс.
7. В зависимости от версии редактора заголовки `FUNCTION_BLOCK/PROGRAM/VAR_GLOBAL` могут переноситься в область объявлений POU, а тела — в область реализации. **Не вставляйте весь текст файла в одну область реализации без разделения объявлений.**
8. Проверьте сборку; ошибки библиотек, типов и маппинга исправляйте по установленному device package. Не объявляйте завершённой до нуля ошибок.

## Pt100 на ПЛК
- В конфигурации одного универсального канала ПЛК200-04-CS выберите Pt100, 3-проводное подключение, и привяжите измеренное значение в °C к `GVL_PC.Pt100TemperatureC`.
- Привяжите аппаратную диагностику обрыва / замыкания / качества измерения к `GVL_PC.Pt100InputValid`.
- До паспортного определения ограничений `TemperatureLimitsConfigured = FALSE`: блок `FB_Pt100Protection` запрещает работу.
- Не ставьте `Pt100InputValid := TRUE` константой.

## Modbus RTU, ПЛК -> INNOVERT
1. В дереве устройств добавьте **Modbus COM Port / Modbus Serial Master** (названия зависят от пакета ОВЕН) на физический RS-485, затем **Modbus Serial Device** с адресом ПЧ 1.
2. Выберите одинаковые параметры 38400 бит/с, 8N1 на обеих сторонах, если они подтверждены дисплеем ПЧ. Для клеммного RS-485 P50.01=13 даёт 38400 (единицы=3), а панельному порту 9600 (десятки=1); заводское 31 даёт 9600 на клеммах. Сначала только чтение.
3. Добавьте каналы FC03/holding: `0x8107` (скорость), `0x8118` (статус), `0x8102` (частота), `0x810A` (ток), `0x812B` (авария), при необходимости `0x8104` (частота датчика скорости).
4. Укажите в I/O Mapping каналы данных `GVL_DriveIO.SpeedRaw/StatusRaw/FrequencyRaw/CurrentRaw/FaultCodeRaw`.
5. **Ответы + свежесть:** `DriveReadFresh` должен формироваться программой как импульс ТОЛЬКО после подтверждённого удачного ответа, а не по факту наличия WORD в буфере. Сначала измерьте период каждого канала и выставьте согласованный тайм-аут.
6. `DriveSpeedSignedRPM` — инженерный параметр декодирования. Не копируйте `SpeedRaw` без проверки масштаба, знака, направления и связи с энкодером.
7. `DriveReportsStopped` — декодированный, подтверждённый на стенде признак останова. Не выставлять TRUE по одному лишь `FrequencyRaw = 0`.
8. Для записей создать последовательный мастер с одной активной транзакцией: FC06 запись частоты (`0x0000`) → успешный ответ → FC06 запись слова (`0x8000`) → успешный ответ. Ограничить частоту операций, проверить, что записи уставки не изнашивают EEPROM. **Этот scheduler ещё не реализован** и выходы `PendingFrequencyWord`/`PendingControlWord` не подключены к Modbus write.
9. При потере Modbus связи нельзя рассчитывать на доставку команды STOP; аппаратная защитная цепь проектируется отдельно.

## Modbus TCP, ПК -> ПЛК
1. Добавьте на Ethernet-адаптер **Modbus TCP Slave/Server**.
2. Создайте область Holding Registers 0..127 с 0-based offset и явно сопоставьте с `GVL_PC.Holding` (если используемый Modbus server требует экземпляра FB/области памяти, реализуйте этот маппинг в нём).
3. Впервые проверьте чтение только телеметрии 100..116.
4. Команды 0..4 должны быть доступны только доверенному компьютеру в изолированной сети. Нужен один писатель, а для эксплуатации — буферизованный транзакционный протокол, чтобы исключить частично записанные команды.
5. Убедитесь в отсутствии регистров типа `40001` в параметрах FC03/FC06 — карта дана в **PDU offsets**.

## Таргет и параметры ПЧ
- По фото двигателя: 220 В Δ, **8,8 А**, 2,2 кВт, 50 Гц, 1420 об/мин. Параметры двигателя записывать по инструкции именно вашего IMD_E-ENC.
- Номинальные 1420 об/мин не означают, что нужно ограничить максимум всегда 1420: допустимые обороты устанавливаются после проверки механики и технологического задания.
- `P61.01` для энкодера может быть 1024, но сначала сверить датчик и проверить счёт A/B. Тип PG и замкнутый векторный режим — только после наладки.
- Карту и особенности MODBUS сверяйте по мануалу и фактическому исполнению платы `-ENC`.
- Ключи `CommissionEnable`, `ConfigValid`, `PGFeedbackProven`, `HardwareSafetyOK` в коде по умолчанию **FALSE**.
