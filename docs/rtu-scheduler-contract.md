# Modbus RTU: реализованный планировщик + границы применения

Код: `codesys/09_FB_InnovertRTU.st`, интеграция: `codesys/08_PRG_MotorMain.st`.

Вместо конфигуратора Modbus COM Port используется официальная OwenCommunication:
- `OCL.COM_Control` открывает один RS-485 с 38400, 8N1.
- `OCL.MB_SerialRequest` на переднем фронте `xExecute` последовательно выполняет FC03 и FC06.
- Автомат: `0` ждать порт, `10` подготовить параметры, `20` выполнить, `30` снять `xExecute`, `40` следующий запрос.
- Чтение: `0x8107` скорость, `0x8118` статус, `0x8102` частота, `0x810A` ток, `0x812B` авария.
- При разрешении записи `RTU_WriteEnable` и разрешении движения от всех блокировок — FC06 запись `0x0000`, подтверждение, затем FC06 запись `0x8000`, подтверждение.
- При ошибке запроса сохраняется счётчик, код/номер операции, скорость и статус немедленно считаются неактуальными; контроль живости и движения блокируется.
- Для каждого циклического чтения контролируется возраст ответа, успешные операции диагностируются отдельно.
- Не добавлять стандартный Modbus COM Port на тот же физический порт: у него будет конфликт с `COM_Control`.

## Важные незавершённые действия

1. Указать реальный `RTU_ComPort` ПЛК200-04-CS и проверить COM-подключение на стенде (по умолчанию 0).
2. Проверить компиляцию ST на установленной библиотеке OwenCommunication и конкретной версии таргета ПЛК200.
3. Сверить `0x8107` с достоверной энкодерной обратной связью; реализовать валидированный декодер знака и масштаба в `DriveSpeedSignedRPM`. Сейчас он по умолчанию 0.
4. Подтвердить и реализовать декодирование `0x8118` как `DriveReportsStopped`; сейчас принудительно FALSE.
5. Установить паспортные температурные пороги Pt100, связать аппаратный канал и диагностику.
6. Реализовать атомарный приём многорегистровой команды TCP и проверенный сброс аварий.
7. Провести функциональное испытание потери RS-485, Ethernet и питания ПЧ, а также аппаратной независимой остановки.
8. Лишь после этого разрешить `RTU_WriteEnable`. **Не использовать отладочный TRUE для обхода защит.**

**Принцип fail-closed:** нет проверенной связи или обратной связи — нет программного разрешения новых команд движения. Это не гарантирует остановку при обрыве RS-485: отдельно обязателен аппаратный безопасный останов и настроенная реакция ПЧ на потерю связи.

### Примечания
- Операции FC06 не заменяют защитного останова; даже подтверждённая запись означает только получение команды ПЧ, не факт физического движения.
- Время профильной рампы ПЛК не гарантирует заданное время изменения механической скорости при инерционной нагрузке.
- Не выполнять постоянную запись EEPROM; проверить семантику `P00.00`.
- Статус файла: ST-код опубликован, но **не скомпилирован и не испытан на оборудовании**.
