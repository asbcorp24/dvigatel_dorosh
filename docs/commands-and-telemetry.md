# Контракт управления от ПК и телеметрии

## Функция управления
`SetMotor(speed_rpm, ramp_seconds, direction)`

- `speed_rpm`: неотрицательная целевая скорость в об/мин; 0 означает плавный останов.
- `ramp_seconds`: время одного этапа движения, значение > 0; при смене направления — отдельно на торможение и отдельно на разгон.
- `direction`: +1 вперёд, −1 назад; на транспорте Modbus направление кодируется 1 и 2.
- `command_id`: уникальный монотонно растущий номер; повтор не должен перезапускать переход.

**Требуемая последовательность реверса**: торможение до нуля → подтвердить фактическую остановку (валидная энкодерная обратная связь + статус ПЧ + выдержка) → переключить направление → разгон. Таймер сам по себе не подтверждает останов.

Промежуточная скорость меняется плавно, но точное время физического достижения зависит от нагрузки, регулятора и ограничений привода. При отсутствии свежего подтверждения ПЧ/энкодера движение не разрешать.

## Предлагаемая карта Modbus TCP
Это **проектные смещения 0-based Holding Registers**, а не автоматически опубликованные адреса ОВЕН. Необходимо реализовать GVL, привязку серверных областей и ограничения прав записи на ПЛК.

| Offset | Направление | Содержимое |
|---|---|---|
| 0 | ПК→ПЛК | Целевая скорость ×10 об/мин, UINT16 |
| 1 | ПК→ПЛК | Время этапа ×10 с, UINT16 |
| 2 | ПК→ПЛК | Направление 1/2 |
| 3 | ПК→ПЛК | Heartbeat, изменять не реже 1 Гц |
| 4 | ПК→ПЛК | CommandID, записывать **последним** |
| 5 | ПК→ПЛК | Зарезервировано: подтверждение аварии, выключено до реализации безопасного сброса |
| 100 | ПЛК→ПК | Последний принятый CommandID |
| 101 | ПЛК→ПК | Состояние автомата |
| 102–103 | ПЛК→ПК | Скорость ×10, signed DINT, high word first |
| 104 | ПЛК→ПК | Pt100 °C ×10, signed INT16, 0x7FFF = нет достоверных данных |
| 105 | ПЛК→ПК | Частота ПЧ, RAW |
| 106 | ПЛК→ПК | Ток ПЧ, RAW |
| 107 | ПЛК→ПК | Статус ПЧ, RAW |
| 108 | ПЛК→ПК | Ошибка ПЧ, RAW |
| 109 | ПЛК→ПК | Свежесть/связь ПЧ |
| 110 | ПЛК→ПК | Обратная связь энкодера проверена |
| 111 | ПЛК→ПК | Pt100 исправен |
| 112 | ПЛК→ПК | Нулевая скорость подтверждена |
| 113 | ПЛК→ПК | Команда частоты ПЧ, RAW |
| 114 | ПЛК→ПК | Командное слово ПЧ, RAW |
| 115 | ПЛК→ПК | Сырой регистр скорости ПЧ |
| 116 | ПЛК→ПК | Разрешение движения |

Запись последнего CommandID сама по себе **не обеспечивает атомарность** многорегистрового пакета при нескольких клиентах или гонках записи. Для эксплуатации нужен отдельный буфер команд, проверка консистентности, блокировка повторного старта и ограничение прав сетевых клиентов.

## Частотник Modbus RTU
Предварительные адреса из документации семейства IMD_E, требуют подтверждения для суффикса ENC:

| PDU offset | Функция |
|---|---|
| 0x0000 | Задание частоты (уточнить изменение RAM/EEPROM) |
| 0x8000 | Командное слово |
| 0x8102 | Выходная частота |
| 0x8107 | Выходная скорость, **не считать доказанной PG обратной связью** |
| 0x810A | Выходной ток |
| 0x8118 | Статус |
| 0x812B | Код неисправности |

Нельзя считать останов безопасно подтверждённым, пока не проверены бит состояния работы и фактическая скорость. RS-485 транспорт должен сериализовать команды, проверять ответы и прерывать разрешение движения при тайм-ауте. Задания привода сохранять в энергонезависимую память только в соответствии с его руководством (не циклической записью параметров EEPROM).
